# Content Preservation Rules

## Core Directive
When updating project documentation, codebases, or text files, you MUST preserve all existing content, technical details, context, and edge cases unless explicitly instructed to remove or refactor them.

## Rules of Engagement

1. **NO Unrequested Simplification:**
   - Do NOT condense, rewrite, or summarize existing text or code for brevity.
   - Do NOT collapse complex explanations, list items, or technical specifications into high-level summaries.

2. **Additive Updates Only:**
   - When adding new feature notes, updates, or specs, append or insert the new content into the existing document layout without modifying surrounding text.
   - Maintain all existing formatting, headings, code snippets, notes, and comments.

3. **No Code Omitting:**
   - Do NOT replace existing functional code, configuration files, or schemas with placeholders such as `// ... existing code ...` or `<!-- remaining text unchanged -->`.

4. **Explicit Refactoring Clause:**
   - Modify, shorten, or remove existing text/code ONLY if the user prompt explicitly requests a rewrite, simplification, or refactoring (e.g., "summarize this section," "clean up redundant text," or "refactor function X").
